# 知华银企智能对账

上海如静知华信息科技有限公司 · [官网](https://www.zhuatech.cn/)

这是一套公开源码的银企流水对账工作台。它遵循一个原则：**系统可以提出有分数和证据的匹配候选，但不能未经独立复核就确认入账**。

## 对账的三道保险

1. **来源去重**：银行流水和账务凭证各有唯一来源号；金额必须为正、最多两位小数，日期不能来自未来。
2. **候选排序**：本地规则比较收付方向、金额、参考号、交易对方和日期。低于阈值或出现同分候选时拒绝自动选择，交由人工登记差异。
3. **复核确认**：另一位审核人员确认后，银行与账务双方状态同步变为 MATCHED，生成不可手工编辑的匹配流水；驳回保留依据。无候选可登记差异并独立关闭。

例如，两笔账务流水都与同一银行流水同分时，`propose` 返回业务冲突，不能随机挑一笔。本场景和正常匹配、重复来源号、越权确认、差异关闭均纳入 HTTP 自动化测试。

业务 H5 包含银行流水、账务流水、候选、已确认匹配和差异台账；管理员可管账号与查看审计。服务端支持租户隔离、幂等、并发版本、附件及 CSV 导出。

## 可替换的分析接口

`cn.zhuatech.reconcileai.InsightProvider` 定义候选生成契约；默认 `LocalInsightProvider` **只使用本地确定性规则，不调用任何真实模型或银行接口**。如果接入国内模型，模型只能提供候选或解释，金额一致性、唯一性、二次复核和入账必须继续在服务端硬校验。真实银行接口、网银授权和 ERP 过账不在本公开版本范围内。

## 开发与验证

Java 21 / Spring Boot 4 / MySQL 8.4，Vue 3 / Vite。复制 `.env.example` 到 `.env` 配置强密码，执行 `docker compose up -d --build`。通过 `sh scripts/test.sh` 运行后端业务验收（本机 H2/MySQL 兼容）、前端单测及构建；CI 配置 MySQL 复测。默认 H5 地址 `http://127.0.0.1:8088`，管理端为 `/admin`，API 健康检查为 `http://127.0.0.1:18080/api/health`。

`GET /api/catalog` 提供模块和动作定义；`POST /api/records/{id}/actions/propose` 提出候选，`confirm` 独立确认。每次写入需携带 `Idempotency-Key`。
